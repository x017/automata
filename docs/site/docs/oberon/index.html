    Oberon

    Oberon is the AUTOMATA editor. It's a native desktop app written in Rust. You build scenes visually and attach Python behaviour scripts. Then you press Play to run the scene inside the editor. Scenes save as plain .ron files, and the same files run from Python with automata.run_scene.

    Run it#

    git clone https://github.com/x017/automata && cd automata
cargo run -p oberon --release              # an empty starter scene
cargo run -p oberon --release level.ron    # open a scene file

    Oberon needs a GPU that supports Vulkan, Metal, or DX12 to render the viewport. Without one it still runs and draws the scene as wireframes, so editing works anywhere.

    For Play mode, Oberon starts a Python interpreter: the project's own .venv, or python3, or the one you pick in Settings → Python. That interpreter needs only the standard library.

    To start a project from the command line, run oberon new mygame. That gives you a level, a typed starter script, tests, and a .venv with the engine and a language server. The oberon command covers this and oberon run, test, export and doctor.

    How Oberon fits with the engine#

              Oberon (Rust)                         Python
 ┌──────────────────────────────┐    JSON    ┌──────────────────┐
 │ scene document · undo        │  per frame │ bridge runner    │
 │ wgpu viewport · physics      │ ─────────▶ │ your scripts'    │
 │ Play loop                    │ ◀───────── │ start / update   │
 └──────────────────────────────┘   writes   └──────────────────┘
              │ Ctrl+S
              ▼
         level.ron ──────────▶ at.run_scene("level.ron")   (the real engine)
    • Editing happens in Rust. The scene is a document with undo history, and every edit is one undo step.
    • Play clones the scene and runs physics and the renderer in Oberon. Your scripts run in a separate Python process. Every frame Oberon sends that process the scene state, and the scripts send back their changes. The process is separate on purpose: a script crash can't take down the editor, and you can switch Python environments without restarting.
    • Stop throws the Play copy away. Your edited scene is unchanged.
    • Shipping doesn't need Oberon at all. at.run_scene("level.ron") runs the same scene and scripts in the engine.
